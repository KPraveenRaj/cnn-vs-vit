# CNNs vs Vision Transformers: A Controlled Comparison under Transfer Learning

M.Tech major project · Signal Processing & Machine Learning, ECE, NIT Karnataka Surathkal · Praveen Raj Konatham

> Vision Transformers now lead image-classification benchmarks, but those results rely on large-scale pre-training and compute, and most published CNN-versus-ViT comparisons vary many factors at once. This project fine-tunes a representative CNN and a representative ViT under a single controlled transfer-learning protocol and compares how the two families behave — beginning with their efficiency in low-data regimes and their robustness to input degradation. The aim is to characterise not just which model scores higher, but how and why each one behaves as it does.

## Design in one paragraph

ResNet-50 (`resnet50.a1_in1k`) vs ViT-B/16 (`vit_base_patch16_224.augreg_in1k`) — both pre-trained on **ImageNet-1k only** — fine-tuned under one controlled protocol on Caltech-256 (primary, clutter class excluded) at nested per-class data fractions {10, 25, 50, 100}% × 3 seeds, plus linear probes on cached features, plus a small Food-101 confirmation. *Controlled* means: identical pre-training source, data splits, augmentation, resolution (224), schedule shape, optimizer family, seeds, and evaluation — with a small documented per-model learning-rate sweep (forcing one LR on both architectures unfairly cripples one). Every checkpoint passes one evaluation battery: clean metrics, corruption robustness (Gaussian noise / blur / JPEG at 5 severities), FFT frequency-sensitivity curves, error overlap, calibration, and deployment cost.

## What every run records

Each run is keyed by a run ID — `{model}_{dataset}_f{frac}_s{seed}_{regime}`, e.g. `resnet50_caltech256_f25_s1_fullft` — and produces:

| Where | What |
|---|---|
| `results/runs/<run_id>/config.yaml` | exact merged config the run used |
| `results/runs/<run_id>/train_log.csv` | per-epoch: loss, top-1, val top-1/top-5, LR, epoch time, imgs/sec, peak VRAM |
| `results/runs/<run_id>/metrics.json` | best val top-1/top-5, best epoch, params, peak VRAM, throughput, wall time, versions |
| `results/runs/<run_id>/clean_eval.json` | frozen-test top-1, top-5, macro-F1, per-class accuracy |
| `results/runs/<run_id>/predictions.parquet` | per-image: filepath, label, prediction, confidence, correct |
| `results/checkpoints/<run_id>/best.pt` | best-val-top-1 weights (not in git — attached to tagged GitHub Releases) |

Run metadata is committed; weights are published as release assets on session tags so any table in the report can be traced back to the exact checkpoint that produced it.

## Reproduce

```bash
pip install -r requirements.txt          # Python >= 3.10, CUDA build of torch

# 1. Place Caltech-256 at data/raw/caltech256/256_ObjectCategories/
# 2. Splits are already committed under data/splits/ — regenerating them
#    (only ever needed from scratch) is: python -m src.data.make_splits --data configs/data_caltech256.yaml
# 3. Train one run, e.g. the f100 seed-0 ResNet baseline:
python -m src.train.train --model configs/model_resnet50.yaml --data configs/data_caltech256.yaml \
    --fraction 100 --seed 0 --regime fullft
# 4. Evaluate its checkpoint on the frozen test set:
python -m src.eval.evaluate --run-id resnet50_caltech256_f100_s0_fullft
# Declared LR sweep (runs before the matrix): scripts/run_lr_sweep_resnet50.sh
```

All figures/tables in the report are generated by script from `results/` — no hand-made numbers.
